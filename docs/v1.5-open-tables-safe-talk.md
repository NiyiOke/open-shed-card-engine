# V1.5 — Open Tables & Safe Table Talk

Status: Epic 1 implemented locally; Epics 2 and 3 remain proposed

Owner: Open Shed

Target: Web, desktop and mobile
Rules profile: unchanged (`merciless-baseline-v1`)

Implementation status: Epic 1 complete locally; public discovery and communication remain disabled pending Epics 2 and 3.

Design flows: [V1.5 Open Tables & Safe Talk FigJam](https://www.figma.com/board/sPLB7KrCfRUUeORpZwlHl6)

The board contains three editable maps: open-table discovery and join, safe table communication, and room lifecycle and cleanup.

## Product promise

V1.5 makes it possible to find a game, join strangers without exposing private identity, communicate safely at the table, keep a game night moving when a host disappears, and remove abandoned rooms from the player experience.

The release remains a game platform, not a general social network.

## Why this release

V1.1 made invited tables reliable: durable links, reconnection, presence, rematches, and server-authoritative play. The next player-visible gaps are connected:

- Signed-out visitors cannot tell whether anyone is waiting to play.
- The authenticated lobby browser shows only a player's private memberships.
- The in-game sidebar explains gameplay events but does not let players communicate.
- A final explicit leave marks a lobby complete, but the row can remain for the longer completed-game retention period.
- Presence can identify disconnection, but a stale host can still strand room authority.
- Rematches do not preserve a lightweight game-night score.

## Goals

1. Show useful, anonymous open-table availability before sign-in.
2. Let hosts explicitly publish a private lobby and let signed-in players join it safely.
3. Add table-only communication with safety controls and privacy-first retention.
4. Close empty or abandoned waiting rooms predictably without breaking ordinary reconnects.
5. Keep a multi-round table usable when the original host does not return.
6. Preserve V1.1's privacy, idempotency, accessibility, and mobile reliability guarantees.

## Non-goals

- Direct messages, public channels, friends/following, public profiles, or a social graph.
- Unrestricted free text in the initial public release.
- Links, contact details, uploads, GIFs, media, custom stickers, or location sharing.
- Voice or video.
- Spectators, global matchmaking ratings, Elo, achievements, or global leaderboards.
- Searchable or permanent chat history.
- Typing indicators, read receipts, push notifications, or a WebSocket migration.
- Host-controlled speech bans or automated permanent sanctions without review.
- AI moderation as the only enforcement mechanism.

## Product principles

### Private by default

Every existing and newly created table is private until its host explicitly publishes it. Publishing never reveals the six-character join code, game ID, account identity, roster, events, or presence timestamps.

### Public identity is a room alias

Joining a public table requires an explicit room alias. Open Shed must not silently publish a ChatGPT account full name. Internal profile identity remains server-only.

### Communication cannot affect the rules engine

Messages, reports, mutes, blocks, unread state, and moderation state live outside `GameState`, `GameCommand`, gameplay revisions, and `game_events`. A chat failure must never prevent a card action.

### Disconnected is not immediately gone

A missed heartbeat first suppresses discovery, then enters an abandonment grace period. A normal mobile interruption must not instantly destroy a room.

## Core experience

### 1. Signed-out open-table discovery

The landing page adds an **Open tables now** module above the final sign-in call to action.

It shows:

- a capped count such as `3 open tables` or `20+ open tables`;
- total open seats, capped at `50+`;
- up to six anonymous table cards containing only occupancy, six-player capacity, pace, rules profile, and coarse waiting age;
- a `Sign in to join` action.

It never shows:

- host or player names;
- join codes, game IDs, profile IDs, player IDs, or a roster;
- chat or gameplay events;
- exact creation time or exact presence time.

If availability cannot load, hide the module rather than claiming that zero tables exist.

Selecting a card preserves the opaque listing intent through sign-in. After sign-in, the user confirms a room alias and the server revalidates the listing before atomically taking a seat.

### 2. Publishing and joining an open table

The lobby gains a host-only `List this table publicly` control with clear preview copy showing what strangers will see.

Initial V1.5 publication rules:

- lobby phase only;
- active host only;
- host is the sole occupant at first publication;
- pace is one controlled value: `casual` or `quick`;
- no custom room title or free-form public description;
- republishing rotates the opaque listing ID;
- starting, closing, expiring, host transfer, or consent withdrawal unlists immediately;
- a rematch never republishes automatically;
- full rooms disappear from discovery and can return if a seat opens while the listing remains valid.

Public join is authenticated and idempotent. It revalidates visibility, host ownership, host presence, consent, phase, expiry, capacity, rules/protocol support, game revision, and state hash in the guarded write.

### 3. Safe table communication

The existing sidebar/drawer becomes two tabs: `Chat` and `Activity`.

V1.5 public message types are:

- allowlisted quick phrases such as `Your turn`, `Nice play`, `One second`, `Ready?`, and `Good game`;
- six to eight unambiguous allowlisted reactions.

The server stores stable phrase/reaction IDs; the client renders localized copy. No arbitrary message body is accepted in the public V1.5 mode.

Desktop behavior:

- sender alias, localized phrase, relative time, and message actions;
- unread count on the Chat tab;
- opening Chat marks visible items read locally;
- copy below the feed says `Table chat disappears after 24 hours`;
- chat is available in lobby, playing, results, and rematch states;
- leaving the table ends access.

Mobile behavior:

- Chat and Activity live inside the existing `Players & activity` disclosure;
- the feed uses a bounded scroll area;
- phrase controls remain inside the expanded panel;
- the panel cannot cover Turn Coach, the hand, or urgent actions;
- message actions and reports use a focus-managed sheet or dialog.

### 4. Mute, block, and report

Every message and player row exposes safety actions in two interactions or fewer.

- **Mute:** reversible, table-scoped, hides that sender's communication and announcements only for the muting player.
- **Block:** persists across tables, silently hides communication, and prevents the pair from being matched through future public-table discovery. It does not change the current round, seating, presence, or turn.
- **Report:** message-specific, rate-limited, confirms receipt, preserves an immutable evidence snapshot, and offers Mute or Block immediately afterward.

Report reasons:

- harassment or bullying;
- hate;
- sexual or grooming behavior;
- threat or self-harm;
- personal information;
- spam or scam;
- cheating or collusion;
- other.

Hosts receive no special communication-moderation power. Platform policy and review own sanctions and appeals.

### 5. Room lifecycle and cleanup

Room lifecycle is orthogonal to round phase.

Definitions:

- **Empty:** zero members whose membership status is not `left`.
- **Abandoned lobby:** a lobby with members but no live or reconnecting heartbeat for the full abandonment grace period.
- **Closed:** non-joinable and absent from discovery/player lists, with a short internal tombstone for replay and audit.

Rules:

1. The final member's explicit leave closes the room in the same guarded transaction.
2. A public host without a heartbeat for 45 seconds suppresses the listing immediately.
3. A lobby with no live or reconnecting member for five minutes closes as abandoned. Any valid heartbeat resets the timer.
4. Closing writes `closed_at`, `close_reason`, closes the listing, removes presence rows, records `room_closed`, and sets a 24-hour tombstone expiry.
5. A closed link returns `ROOM_CLOSED`; replaying the final leave with the same command ID returns its durable result.
6. If a host leaves while members remain, authority transfers to the lowest active seat and the public listing closes. The successor must publish again explicitly.
7. Complete-game members may explicitly leave; a completed room with no remaining members closes.
8. Never use `beforeunload` as proof that someone left.

The lazy cleanup worker closes and purges bounded batches during ordinary public-list, lobby-list, game-read, presence, and mutation requests. A future scheduler may make timing more exact without changing the lifecycle contract.

### 6. Host recovery and round series

These are P1 epics within V1.5 because they complete the same social game-night promise.

- After the existing two-minute server-verified grace period, the next connected active seat may choose `Keep table going` and claim host authority.
- Claiming host does not automatically remove the former host.
- If the former host reconnects first, the claim fails safely.
- Each completed round creates exactly one immutable round record keyed by game and completion revision.
- Results and rematch lobby show round number, wins per player, and the five most recent winners.
- Series scoring is room-only wins; no Elo, points table, achievements, or global ranking.

## Data contract

### Discovery and lifecycle

Add to `games`:

```text
room_status       open | closed
closed_at         nullable server timestamp
close_reason      nullable empty | abandoned | host_closed | expired
abandoned_since   nullable server timestamp
```

Add to `game_members`:

```text
public_discovery_consent_at  nullable timestamp
join_source                  host | invite | public
```

Add `public_game_listings`:

```text
game_id             primary key
listing_id          unique random 128-bit-or-stronger locator
owner_profile_id    private host identity
state               listed | unlisted | closed
pace                casual | quick
version              integer
published_at         server timestamp
updated_at           server timestamp
unlisted_at          nullable timestamp
close_reason         nullable text
```

Indexes:

- unique `listing_id`;
- `(state, updated_at)`;
- `(room_status, closed_at)` for bounded cleanup.

### Communication

Add `game_messages`:

```text
id                   random opaque message ID
game_id              table
sender_profile_id    server-derived identity
kind                 phrase | reaction
content_id           allowlisted semantic ID
created_at           server timestamp
expires_at           rolling 24-hour expiry
```

Add `game_message_reports` with reporter, message evidence snapshot, reason, moderation state, created time, and restricted evidence expiry.

Add table-scoped `game_mutes` and persistent `profile_blocks`. Blocks are evaluated in both directions for public discovery/join eligibility while remaining invisible to the blocked player.

### Round series

Add `game_rounds` keyed by `(game_id, completion_revision)` with winner profile, winner display-name snapshot, reason, and completion time. Write the record in the same guarded D1 batch as the winning transition.

## API contract

### Discovery

- `GET /api/public/availability` — unauthenticated capped counts, cacheable for 30 seconds, creates no profile.
- `GET /api/public/rooms?cursor=...` — unauthenticated anonymous cards, maximum six before sign-in and twenty after sign-in.
- `POST /api/public/rooms/:listingId/join` — authenticated, idempotent, atomic public join.
- `POST /api/public/quick-join` — authenticated server-selected eligible table.
- `POST /api/games/:gameId/listing` — host-only publish/unpublish with command ID, expected game revision, and expected listing version.

### Communication

- `GET /api/games/:gameId/messages?cursor=...` — member-only bounded page.
- `POST /api/games/:gameId/messages` — member-only idempotent phrase/reaction send.
- `POST /api/messages/:messageId/report` — member-only report with immutable evidence snapshot.
- `PUT|DELETE /api/games/:gameId/players/:playerId/mute` — table-scoped mute.
- `PUT|DELETE /api/games/:gameId/players/:playerId/block` — persistent block without exposing profile identity.

All mutations use same-origin JSON checks, bounded bodies, actor-derived identity, durable receipts where replay matters, and user/table/listing quotas.

## Communication safety and privacy

- One send every two seconds and ten sends per minute per user, plus duplicate-burst suppression.
- Current authenticated table members only; no message access after leaving.
- Messages expire after 24 hours or table purge, whichever comes first.
- Report evidence may be retained for up to 90 days pending policy and legal sign-off.
- Message content never enters analytics, general application logs, crash reports, or `game_events`.
- Analytics contain counts and latency only.
- A global kill switch independently disables public discovery, communication, or free text without a deployment.

Epic 1 defines the fail-closed switches below. Only the exact value `true` enables a capability, and free text remains disabled unless communication is also enabled:

```text
OPEN_SHED_V15_DISCOVERY_ENABLED
OPEN_SHED_V15_COMMUNICATION_ENABLED
OPEN_SHED_V15_FREE_TEXT_ENABLED
```

### Free-text launch gates

Typed free text stays off unless all gates are signed off:

1. Child-access/risk assessment and privacy impact assessment for target markets.
2. Defensible age/eligibility treatment; self-attestation is not described as verification.
3. Published community rules, privacy notice, retention/deletion policy, and appeal path.
4. Operational moderation queue with named owners, triage/escalation targets, and an urgent-harm procedure.
5. Unicode normalization, 160-grapheme limit, contact/link rejection, spam controls, and tested moderation filters.
6. End-to-end account sanctions, evidence preservation, deletion, appeal, and user-data request handling.
7. A closed pilot with acceptable harm, false-positive, latency, and moderator-load measurements.

## Accessibility requirements

- Chat is a labelled `role="log"` with user-controlled polite announcements.
- Muting also suppresses announcements from that sender.
- New messages never steal focus or reset the user's scroll position.
- All controls have visible focus, descriptive accessible names, text status in addition to color, and 44px minimum touch targets.
- Phrase IDs resolve to localized text before assistive technology announces them.
- At 320px and with a virtual keyboard open, communication never obscures Turn Coach, the hand, or urgent actions.
- Report, mute, block, publish, join, closure, and recovery dialogs trap focus, support Escape, and restore the trigger.

## Success metrics

Discovery:

- At least 90% of clicks on a currently eligible table result in a joined lobby or a precise safe failure.
- At least 25% of signed-out visitors who see availability open sign-in; establish the final target after a baseline period.
- Zero private fields in public payload contract tests and production sampling.

Lifecycle:

- Final explicit leave removes a room from player-facing lists within one response.
- Abandoned public lobbies disappear from discovery within one minute of crossing the five-minute grace.
- Zero joins succeed after logical closure.

Communication:

- At least 99.5% of accepted sends appear by the next two poll cycles.
- p95 send-to-visible time is under three seconds.
- Duplicate message rate remains below 0.1%.
- One hundred percent of sampled normal messages are deleted within policy.
- No message content appears in analytics/log audits.

Game-night continuity:

- Completed-table-to-next-round start rate improves by at least 20% from the V1.1 baseline.
- Exactly one round record exists per completion revision under retries and races.
- Eligible host recovery restores authority within five seconds for at least 95% of attempts.

Safety guardrails:

- report rate, block/mute rate, repeated-reported-account rate, severe reports, and triage time stay inside published pilot thresholds;
- no material increase in mid-game abandonment, moderation backlog, false-positive rejection, API cost, or accessibility defects.

## Acceptance journey

The V1.5 release demo must prove:

`host creates private table → host publishes with an alias → signed-out visitor sees anonymous availability → visitor selects a table → sign-in preserves intent → server atomically joins or gives a precise full/closed result → players exchange quick phrases → recipient mutes, reports, and blocks without affecting play → round completes once under lost-response retry → rematch preserves score → host disconnects → recovery is unavailable during grace → eligible player keeps the table going → everyone leaves → listing disappears and stale links return Room closed`

The same journey must pass with:

- three isolated identities;
- desktop and 320px mobile;
- keyboard, touch, reduced motion, and screen reader checks;
- simulated network loss and server-controlled time;
- start/join, unpublish/join, final-leave/join, host-claim, and duplicate-send races;
- recursive forbidden-key tests for public DTOs;
- message retention, report evidence, and log-redaction tests.
