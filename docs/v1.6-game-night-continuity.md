# Open Shed V1.6 — Game Night Continuity

## Product outcome

Keep an established table moving across temporary host loss and multiple rounds without weakening the server-authoritative game boundary. V1.6 is a backwards-compatible feature release, not a new rules profile.

## Release sequence

- **V1.5.1 — Release identity:** establish one canonical application version, show it quietly in signed-in and signed-out modes, separate it from the rules profile, and relabel mutable `STATE vN` copy as `TABLE REVISION N`.
- **V1.6.0 — Game Night Continuity:** add server-verified host recovery, an immutable round ledger, persistent series scores, recent winners, and rematch continuity.

## Host recovery contract

- A player never becomes host from a client-side timer. The server derives eligibility from current membership, current presence, game state, and the existing two-minute inactive threshold.
- The existing host remains host during the reconnecting/disconnected grace window. A claim becomes available only at or beyond the two-minute threshold.
- Lobby and playing claims require an active claimant. A completed table permits any present non-left member, including a Mercy-eliminated player, to recover the table for a rematch.
- The claimant must still be connected at the server's 45-second disconnected boundary.
- If several players could claim, the server selects one deterministic seat: the first eligible connected seat in play order after the old host.
- Claiming changes authority only. It does not remove the former host, alter hands, change a turn, reset readiness, or rewrite the round result.
- The mutation is revision-bound, durable-idempotent, and guarded in the same D1 batch as its receipt, public event, membership roles, and game snapshot. Concurrent claims admit exactly one winner.
- A former host heartbeat that commits before the claim guard makes the claim fail safely.

## Round and series contract

- Each `playing → complete` transition with a winner writes one immutable round result keyed by `(game_id, completion_revision)`.
- A second unique constraint on `(game_id, round_number)` prevents two results for one round.
- Lost responses and command retries cannot duplicate wins.
- Rematch, host transfer, host claim, disconnect, and reconnect never delete or reset the ledger.
- The player view exposes only table-safe presentation data: round number, total completed rounds, current-member scores, and at most five recent current-member winners.
- Profile IDs, auth subjects, departed aliases, private hands, and historical membership are never projected.
- A public player who joins later cannot see departed private-table aliases. Historical wins remain durable internally but are shown only when the winner maps to a current non-left player, using that player's current table alias.

## Player experience

- A connected eligible player sees `Host unavailable` and a single `Keep table going` action after the server grace period.
- The action explains that it changes host authority while keeping players, cards, turn, and series intact.
- Results show `Round N complete`, ranked series wins, and up to five recent winners.
- The host action becomes `Play round N+1` and explains that the table, players, and score continue.
- Application version appears in an About/What’s New surface and in privacy-safe issue diagnostics. Table revision and rules profile remain separately labelled.

## Non-goals

- Removing the absent host automatically.
- Electing a host from client clocks or optimistic UI.
- Changing No Mercy rules, scoring card values, or introducing ranked matchmaking.
- Public live voice, stored voice notes, WebSocket transport, spectators, or a social graph.
- A permanent global player profile or cross-table leaderboard.

## Release gates

1. Three isolated players complete: play → host disconnect → no claim before grace → one eligible claim after grace → simultaneous claim race has one winner → old host remains seated → gameplay continues.
2. A completed round under a deliberately lost response produces exactly one ledger row and one win. Same-key replay returns the same result; different-body reuse fails.
3. Rematch opens round N+1 and preserves scores through rematch and host recovery. Final leave still closes the room.
4. A former/private departed alias never appears in a later public joiner's view, event feed, series score, recent winners, DOM, accessible name, URL, or diagnostics.
5. Desktop and 320px browser checks cover the claim banner, pending/retry state, result score, recent winners, About dialog, focus restoration, 44px controls, reduced motion, and no horizontal overflow.
6. Migration generation/drift, real SQLite/D1 constraints, full unit tests, TypeScript, lint, production build, production dependency audit, required game client, and visual inspection all pass.
7. UI, package metadata, release notes, diagnostics, Git tag, and hosted release report one canonical semantic version. `TABLE REVISION N` remains explicitly distinct.

## Implementation status

The V1.6 player UI is bound to the server-projected `canClaimHost` and `series`
contracts. Equal-revision polls refresh presence-derived viewer capabilities
without admitting older gameplay snapshots. Desktop and 320px checks cover the
host-recovery action, results dashboard, series score, recent winners, and
round-preserving rematch; integrated database race, migration, build, and
deployment gates remain part of the release handoff.
